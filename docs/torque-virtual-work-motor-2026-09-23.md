These are finite-step, trapezoid-rule balance checks on a **changing-current** path, not independent instantaneous torque or a frozen-current derivative. The small discrepancy to Maxwell could include quadrature and discretization error; the present data do not apportion it. This check assumes the no-eddy current-driven port convention used by this run and the stored-potential convention validated in the reconstruction note.

For a reversible fixed-current equilibrium, define whole-machine `W′(i,θ) = Σ_p i_p ψ_p(i,θ) − U(i,θ)`. At fixed three-phase current, the torque is `∂W′/∂θ`; equivalently it is minus the rotor derivative of the current-source potential `U−Σ iψ`. The PM term is already in `U` as `−H_c·B`, and the winding source belongs in `−Σiψ`. Use the same coil-linkage scaling as the existing raw waveform, including sectors, stack and parallel-path convention. Any θ-independent PM or flux-linkage reference constant cancels in a central difference. **Do not** differentiate `U` alone along run04's varying-current trajectory.

`fem_solver_2d.py` rounds `θ/spacing` to an integer `m_shift`, then calls `SlipProjection.build(m_shift)` (around lines 5776 and 5852). The weld classes change at these shifts, so a derivative of a fixed reduced coefficient vector through `P(m)` is not mathematically the equilibrium shape derivative. A valid available route is to solve the complete nonlinear equilibrium separately at the snapped angles, preserving each solve's own weld projection, and compare scalar `W′` values. All three solutions must impose the **same phase-current vector** as saved frame 0 and use the same no-loss, fixed PM/material state; do not let the waveform sample a different current at displaced angles. The existing frame-0 state supplies the center; it does not supply either neighboring equilibrium.
