# Propeller S1 point: physical limit sources

**Scope.** Read-only inspection of the isolated release source on 2026-10-07. This note maps the numerical sources the point evaluator can use for thermal, electrical, and mechanical gates. It does not certify an operating point, alter a solver, or claim a propeller-loaded S1 maximum.

## Gate evidence available in the unchanged code

| Gate | Existing limit and same-point observation | Qualification boundary |
| --- | --- | --- |
| Thermal | `routes/coupled.py` computes the same run's `time_to_limit` via `_ttl_step`; `coupled_time_to_limit.part_limits()` supplies per-part `limit_c`, `limit_source`, and `at_point_c`. The `solve()` result carries `within_limits`, `limits_c`, `at_point_c`, and `judged` (`coupled_time_to_limit.py:257-318, 608-749`; coupled insertion at `routes/coupled.py:6685-6686`). Use this run's explicit `within_limits` plus the per-part rows and named limit sources. | `within_limits=true` alone is not sufficient: the model can have no judged parts. Require a non-empty, appropriate `judged` set; require winding coverage, and require a magnet limit when a magnet is present. Missing limit/source or missing same-point observation means `unknown`, not pass. Winding's current project limit is 200 °C, Class N per IEC 60085, but source code labels it **assumed because no card carries a rating** (`report.py:4814`; `coupled_time_to_limit.py:188`). The assigned magnet card may provide `max_working_temp_c`; otherwise the grade-name rule is attempted and absent evidence leaves magnets unjudged (`coupled_time_to_limit.py:199-225`). Bearing temperature is judged only if the run identifies bearings and a lubricant card states its limit (`:231-250`). Optional heat-path housing/structure uses the fixed 70 °C touch policy, only when that path is present (`:302-318`). Preserve these qualifications in any evidence record. |
| Electrical | A real controller-backed phase-current ceiling exists in `configure_limits.current_limit(ctrl)`: at 100 °C case temperature it reads the selected controller device's datasheet `DeviceCard.i_d_rating(100)` and returns `i_phase_rms_max_A = sqrt(2) * I_D * devices_parallel`, with device, count, rating basis/source, case temperature, and junction maximum (`configure_limits.py:21-80`; card implementation/ratings at `inverter/devices.py:244-254, 620-722`). PWM feasibility also requires its actual current/voltage target and convergence evidence. A body-only `I_phase_rms` sweep does not retarget a saved inverter target: `_inverter_settings` retains `inverter.target_I_phase_rms_A`, and the PWM regulator moves the fundamental to chase it (`routes/coupled.py:841-911, 2611-2698`). |

Do not use an RPM search ceiling or requested speed as a mechanical limit. The route's overspeed factor chooses an additional stress case; it is not an RPM capability value (`routes/mechanical.py:624-642, 1751-1890`). |

## Current-limit source audit

There is **no motor current-drive phase-current capability** in the Simulation settings schema. The example `config/motor_config.yaml` stores `simulation.max_current`, `simulation.current_a`, and `simulation.drive: current` (`:431-446`); these are selected study inputs. The Simulation route uses `max_current` as the current input when no request value is supplied (`routes/simulation.py:2362`) and mirrors `max_current`/`current_a` as configuration fields (`:266-277, 524-527`). The schema comment calls `max_current` “Peak coil current,” while the coupled/field request and its reported current use RMS conventions; use an explicit `I_phase_rms` trial value and canonical `I_winding_rms_A` readback. These fields are not an equipment limit and must not be copied into `drive.settings.current_limit_a`.

This matters because `coupled_propeller_s1_point.evaluate_propeller_rpm()` requires a positive `drive_current_limit_a` and requires the identical value to appear in `identity.drive.settings.current_limit_a`, `current_limit_rms_a`, or `limit_a` (`coupled_propeller_s1_point.py:425-486`). An earlier private-bridge draft filled `configured_current_limit` from `simulation.max_current`/`simulation.current_a`; the current bridge now records those separately as operating setpoints and leaves `current_limit_a` null (`coupled_propeller_s1_private_bridge.py:246-255`). The fail-closed behavior is correct until an authoritative ceiling is wired in; the gate cannot become true from the config setpoint.

The existing `configure_limits.current_limit()` is a valid sourced ceiling only for a configuration with an identified Controller device and device count. It returns `set:false` when there is no Controller device or the card does not publish a continuous rating (`configure_limits.py:49-80`). For that controller-derived ceiling, bind the actual resolved Controller device/count and rating source to the same configuration as the trial. Do not apply this value to an unrelated Controller, or infer a motor-current rating from it without stating that it is the inverter-side ceiling.

## Minimum supported point-driving contract

For the current point adapter and private bridge as implemented, use the canonical current-drive coupled path with an explicit `I_phase_rms` value at each trial, explicit RPM, and `solve_to="steady"`; the bridge currently refuses non-current drive modes (`coupled_propeller_s1_private_bridge.py:241-244`). The body must preserve selected geometry, winding connection, materials, pack, and thermal source. A successful `P_shaft_net_W` and `I_winding_rms_A` are the required same-point delivered mechanical output and current observation; current is winding RMS, while terminal `I_phase_rms_A` differs by √3 in delta (`routes/simulation.py:7281, 7774`; adapter extraction at `coupled_propeller_s1_point.py:187-212`). For a future PWM/controller sweep, body-only current changes are insufficient: set the saved target to each trial current or the PWM regulator will chase its prior target. The route preflight also requires the stored/requested eddy and rotor-eddy controls to remain enabled for a coupled run (`routes/coupled.py:2507-2547`); do not silently turn them on.

Before an electrical gate can be `true`, the trial needs an authoritative limit associated with this exact configuration: either (a) a named, sourced motor/current-drive limit introduced through an existing approved input, or (b) a resolved Controller datasheet limit from `configure_limits.current_limit()` where the product requirement is specifically to stay inside that inverter ceiling. The caller's `current_max_a` is only a search bound; it is not the limit. Until such an input exists and is tied to the frozen build, mark the electrical current-limit gate `unknown`; report the actual solved current and provenance without calling it a pass.

For PWM/controller points, either set each `inverter.target_I_phase_rms_A` to the sampled trial current and validate the actual returned point, or use the current-drive path above. A PWM trial is not a current sweep merely because `I_phase_rms` changed: the saved target may cause the regulator to change fundamental voltage to recover the old current target. The controller path should additionally report actual target error/convergence, modulation/DC feasibility, and controller junction temperature versus the card's `t_j_max_c`; `i_d_rating_A` alone is not a full PWM electrical gate.

For mechanics, record the same-trial `rpm`, torque, temperatures, geometry and resolved mechanical materials/settings alongside `sf_min`/`sf_min_p05`, and compare only to an explicit policy source such as `report.SF_ACCEPT`. If that policy is not part of the actual qualification contract or stress solve fails, leave the gate unknown. In no case should a failed/nonconverged solve be converted into a physical upper bound.

## Immediate bridge correction

The next mapper should source `drive.settings` from the resolved drive and configuration, keep the raw source and units, and check the actual same-point observation against that sourced ceiling. It must refuse to label `simulation.max_current`, `simulation.current_a`, current-search `current_max_a`, PWM target current, or a requested RPM as a capability limit. For the current-drive S1 feature as currently wired, no source-backed motor current limit was found in the Simulation config; until product supplies one, electrical current-limit qualification is unresolved even when the thermal and propeller torque checks pass.

## Averaging clarification after full source audit
The full rotor-stress solver stores sf_min as the minimum of its per-part AVERAGED safety factors, not the minimum element factor. sf_min_unaveraged and sf_min_p05 are separate diagnostics. A gate must retain and cross-check per-part strength, governing averaged stress and factor, together with same-run mechanical arguments/thermal temperatures. The compact coupled block does not provide that full evidence. Existing source policy report.SF_ACCEPT=2.0 is available but must be explicitly versioned/hash-bound in the qualification contract; the separate limit-speed search default1.0 must not silently replace it. See docs/propeller-s1-mechanical-gate-contract-2026-10-07.md. No mechanical solve was performed for this clarification.
