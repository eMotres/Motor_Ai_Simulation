# Corrected-linkage motor state checkpoint — 2026-09-23

Run15 is one isolated repetition of the archived GEO30 12-slot/14-pole, two-sector, no-eddy, no-demagnetization, imposed-current P2 case: 60 A phase RMS, 15,000 rpm, 48 steps per electrical period for two periods, mesh settings 1.4/0.35 mm. The guarded runner saved all 96 raw phase-current/linkage/torque/angle samples and complete selected P2 states at frames 0, 1, 48 and 49, including quadrature B, assembled B-H curves, PM and winding sources. It pinned the run04 configuration and material-library hashes, recorded the corrected solver/source hashes and git HEAD, and wrote only to its unique scratch directory. Its preflight had no solver import or FEM call. The actual run finished in 57.96 s; all 96 frames converged, with no Picard fallback or unconverged frame. `scripts/torque_corrected_state_review.py` only reads these saved files; it starts no solver.

The corrected no-eddy P2 linkage equals `stack·sectors/n_parallel · A·f_coil` at all four selected states: independently recomputing each phase from saved `A_z` and source vectors gives maximum discrepancy **1.08e−19 Wb** (capture-time rounded differences were 0 Wb). The review verifies the live production `field_ops.py` hash against run15 provenance before comparing its B-H law. It also checks each saved frame's angle against the waveform and rejects mismatched stack/sector/parallel scales, eddy, demagnetization, frozen-ν, voltage drive or unconverged selected states. The reconstructed whole-machine magnetic potential integrates the production pointwise nonlinear `∫H dB`, linear `½νB²`, and PM `−Hc·B` at P2 quadrature. On 73,224 sampled nonlinear quadrature values, reconstructed `H` differs from production by at most `2.33e−10 A/m`; no sampled value enters production's `B≤1e−12 T` branch. The permeability floor is inactive both at sampled B and at all curve knots along the integration paths. The PM field integral equals the negative assembled PM-source dot product to `2.22e−16 J`.

The 24-to-48-step terminal-work change is **0.8512%** relative to the 48-step value, above the existing diagnostic helper's default 0.1% coarsening limit; the current window would therefore fail that sampling gate. For a *pure fundamental* sinusoidal current/linkage pair, this endpoint trapezoid has the exact factor `sin(2π/48)/(2π/48) = 0.9971466573`. Applying that factor to the hybrid mean gives 0.4084783264 N·m, close to the measured 0.4084796911 N·m. This explains the likely dominant sampling bias but is a hypothesis about the motor's waveform content, not permission to divide the motor result by a sinusoidal factor. The raw Maxwell difference from terminal work is +0.0002799067 N·m, without a validated uncertainty bound.

**Status remains uncertified.** The PM-inclusive potential difference divided by angle is only an arithmetic comparison; it is not a proven port-energy correction. Four selected full states cannot certify the whole periodic material trajectory, and 48 angular intervals do not pass the default coarsening check. No independent converged period-mean virtual-work reference or mesh/angular error bound is available. The >1 A selector was not changed, no samples were filtered, and this note does not designate a replacement torque formula. Separate run stderr mentioned core-loss ramp handling; that issue was not investigated here and does not alter the saved raw torque waveforms.

The 24-to-48 difference falls from 0.8512% for trapezoids to **0.01092%** for cubic/Gauss; 12-to-48 cubic difference is **0.11661%**. This supports second-order trapezoidal quadrature bias as the dominant cause of the earlier sampling change. It does not prove angular convergence or a torque formula: cubic interpolation supplies no new field samples and can share aliasing with the original grid. The 48-interval cubic value is close to the hybrid mean (difference +1.59e−6 N·m), but these are not independent torque measurements. Exact endpoint magnetic potential change might in principle replace a strict periodicity requirement in a *validated* electromechanical port-energy identity; that identity, PM reference convention and moving integer-weld consistency have not been established here, so the arithmetic potential correction remains uncertified.

Recheck the discrete weld's source/field mapping and refine slip spacing before treating that secant as a derivative. Run09 provides preliminary ±cell secants but no weld/refinement error bound, so this remains a proposed gate, not a new motor result.
