# Private S1 worker process-control checkpoint

Date: 2026-10-07. Model: GPT-6, escalated from the stopped Sonnet 5.5 draft after review failures. This is fake-hook software testing only; the process helper is not wired into the bridge and no child worker, FEM, API, or deployment was run.

The initial draft failed its first Windows-host run: it evaluated `os.killpg` as a default argument at import time and assumed `signal.SIGKILL` existed. It also synchronously wrote stdin through a pipe, swallowed group-signal and `wait()` errors, created a colliding attempt directory, and wrote an ad hoc checkpoint after execution. That version's test attempt produced 8 failures, 10 passes, and 1 platform skip; this negative result is retained here rather than treated as a dependency issue.

The replacement helper is Linux-runtime-only and resolves process-group hooks at call time. Off Linux, tests must inject fake group hooks. It requires an already-existing private job marker and attempt directory beneath `attempts/`; it does not create or overwrite the caller's attempt directory. The process checkpoint is atomically created with no-replace semantics. Existing raw solver artifacts remain untouched.

Worker stdin is supplied from an anonymous file-backed stream, so parent-side writes cannot hang on a child that is not draining a pipe. Stdout and stderr use anonymous temporary files and are discarded after completion. The only returned stdout is a bounded, parsed JSON object with sensitive-key rejection; raw streams, command, environment, and exception text are not recorded. Checkpoint states and return codes are valid JSON, and every spawn, cancellation, timeout, nonzero exit, invalid output, and cleanup failure has a fixed sanitized reason code.

Cancellation and timeout send TERM to the worker's own session/process group, wait for the group to disappear, then send KILL if needed. Even after the leader exits successfully, the helper probes for remaining group descendants and cleans them up. It waits to reap the leader and returns `cleanup_failed` if signaling, group probing, or reaping cannot be confirmed; these failures are not swallowed. Fake tests assert every signal targets only the worker's PGID.

Parent review found that the first replacement draft checked the process group before reaping the leader, did not clean up if closing the stdin spool failed after spawn, and allowed duplicate workers to race before checkpoint creation. The current helper now waits/reaps the leader before final process-group verification, puts teardown in a `finally` block with a bounded emergency kill/reap fallback, treats post-spawn clock/sleep failures as control failures after cleanup, and re-raises `BaseException` only after a sanitized checkpoint is written. A no-replace `.process-attempt.lock` is atomically reserved before cancellation checks or spawning; a concurrent/repeated attempt is refused.

Verification: `tests/test_propeller_s1_process.py` **26 passed, 1 skipped** under Python 3.11 on Windows. The skip is the host-dependent symlink fixture. Tests use an injected fake Popen/process and fake process-group hooks; no real process is launched. Cases include a zombie-like leader reported by the fake group probe until `wait()` reaps it, delayed group disappearance after SIGKILL, stdin-spool close failure after a successful fake spawn, clock/sleep exceptions after spawn, and a `KeyboardInterrupt` from the cancellation callback. Existing checks also cover cancellation before/during execution, timeout and forced kill, descendants after leader exit, nonzero/invalid output, sanitized failures, reaping and cleanup failure, attempt reservation/checkpoint exclusivity, preservation of earlier solver artifacts, path containment, symlinks, file-backed large stdin, and invalid timeouts/cancel callbacks.

The private bridge now serializes its worker request to UTF-8 bytes and calls this helper with the existing attempt directory, private job root, trial-config environment, timeout, and optional cancellation callback. It validates the returned attempt-local process checkpoint against the outcome before consuming parsed worker JSON. It does not use blocking `subprocess.run`, persist raw stderr, or include bearer authorization in bridge metadata. An explicitly injected runner is the test seam; the default runner refuses on non-Linux hosts. Process cancellation becomes a fatal cancelled S1 job result; timeout, worker failure, malformed checkpoints, and cleanup/control failures become fatal failed job results. The job binds its cancellation predicate to the bridge before search begins, and the fatal control path bypasses point/search recovery so no additional callback launches.

Verification after bridge/job wiring: the focused bridge, job, process, point, search, trial-context, and voltage-evidence suites report **182 passed, 4 skipped in 22.47 seconds** on Python 3.11. The skips are platform-dependent symlink cases. The process helper itself is exercised only through fake Popen/process/group hooks, and bridge integration tests inject a fake process runner; no child process or FEM was executed. A proposed lightweight real Linux process smoke was rejected by automatic review because it required explicit destination/payload approval; it was not run or retried. Therefore actual Linux process-group behavior remains unverified in this checkpoint. Syntax compilation and `git diff --check` passed for owned files.

Process control is lifecycle handling only; the bridge/job still do not claim a maximum RPM or physical qualification. No solver logic, live API, deployment, or UI was changed.
