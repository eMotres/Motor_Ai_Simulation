## Next-stage API

Import from `motor_ai_sim.gears`. Construct `GearboxRequest(stages, operation='point'|'spectrum'|'assembly'|'pose', request_id=..., ...)`; `execute()` returns `GearboxResponse`. Preserve supplied stage_id/request_id; stage IDs survive display-name changes and reordering. Defaults create UUIDs only when constructing new requests/stages.
Every response envelope includes `core_version='gear-core-r4'`, `request_hash` and `member_instances`. Hash = SHA-256 of full canonical request JSON, sorted keys, compact separators, UTF-8; it includes IDs, options and inline specs. It is input provenance, not a result integrity signature. Referenced catalogue contents are not hashed; cache owners must also pin catalogue/source revisions.
`member_instances` maps aggregate target IDs to physical member IDs: `stage_planet.planet -> stage_planet.planet_0..2`; singleton roles map to one ID. Stage `member_ids` maps role to aggregate ID. Carrier is a conceptual ID without a rendered gear placement. Compound planet2 has its own instances.
Use `response.result.passed` with `pass_reasons` for spectrum qualification. It combines overall state, preset and supplied parts. `estimated` may pass thresholds but must retain that label. Point results deliberately have passed=false with preset/parts-not-evaluated reasons; they are not full-duty qualification.
`to_dict()` / class `.from_dict()` use recursive v1 records with schema_type, schema_version and metric_availability; `json.dumps(...,allow_nan=False)` is supported. Numeric null is not zero. Endurance is null plus status=endurance/nonfinite=positive_infinity, restored as infinity on decode. Individual Miner endurance retains its zero-damage flag; failed individual bearing life is diagnostic only.
Decoder rejects unknown/missing fields, bad types/versions and inconsistent derived availability/combined pass. It requires complete canonical records, including r4 additions; older r3 envelopes need reconstruction/migration through constructors. This is not authentication or tamper-proof storage.
`FieldValidationError(ValueError)` exposes path (RFC6901), code and message, plus `to_dict()`. Nested decoder, request reference, duplicate-ID and numeric errors have field paths; cross-field errors may name the enclosing record. Legacy low-level constructors can still raise plain ValueError; routes should enter through the request/decoder boundary. No JSON Schema/OpenAPI exporter was added.
Catalogues: `list_material_catalogue()` (7), `list_lubricant_catalogue()` (6), `list_bearing_catalogue()` (12), `list_preset_catalogue()` (2). Lists contain names and key properties, JSON-safe; bearing `core_supported` indicates card eligibility. Bearing request specs can use `GearBearingSpec.from_library(name)`; supply Cu_kn when known. Materials include provenance; preset proposed fields remain explicit.
Pose: request `operation='pose', input_angle_deg=37` returns `AssemblyPose(input_angle_deg,members)` in the same response envelope. Members are keyed by display name but carry stable member_id. It matches `build_chain_assembly(stages).pose_at(angle)`: rotation=reference+speed_ratio*angle; planet orbit=reference_orbit+carrier_ratio*angle around carrier_center.
Assembly options: `outline_once=True` stores each identical outline in `result.outlines[outline_id]`, with placement.outline=null; resolve via outline_id. `outline_stride=4` samples every fourth vertex and recloses the polygon; default1 retains full detail. `AssemblyDescription.with_outline_options(stride=...,once=...)` returns a new description and preserves poses. Decimation is viewer-only with no manufacturing error bound.
Two-stage example: 40/20/80 N=3 planetary +20/40 pair, m1/b12, seven placements. Compact UTF-8 response size: **4,077,066 bytes full; 2,402,616 outline-once; 624,851 stride4+once** (84.67% reduction from full). Includes availability metadata; pretty JSON is larger. Inputs/hashes are saved in evidence.
DutySpectrum bins are output torque Nm, output rpm, duration h and ambient C; required life comes from preset. Rated duty S_H/S_F use repeated-block per-member cycle exposure; Miner independently integrates actual stresses/cycles. Direct `evaluate_stage` accepts `member_cycles` override; the obsolete fixed cycles_default argument was removed.
Peak fields: peak_torque_out_Nm, integer peak_events, explicit peak_speed_out_rpm (zero is known), peak_member_engagements keyed by aggregate tooth ID (per tooth per event), static_strength_limits keyed likewise, peak_reversing. `StaticStrengthLimits(source,temperature_C,root_MPa,flank_MPa)` requires physical allowables at matching temperature; carrier/unknown tooth IDs reject.
Missing peak speed/count disables event fatigue. Supplied peaks use K_A=1; absent declared peak uses flagged preset-shock static estimate without invented event damage. Static and fatigue states remain separate. `cycles_for_*_stress` now returns Optional[float]; handle None above the static plateau.
TransmissionIR export remains outside this dataclass envelope (`model_dump(mode='json')`), rejects invalid assembly, and retains partial/unqualified, motoring-only provenance. Catalogue gearbox checks remain a separate estimated datasheet path. No HTTP routes or storage layer were added.

## Opt-in mesh misalignment input (2026-11-26)

`PairStageSpec.f_ma_um`, `PlanetaryStageSpec.sun_planet_f_ma_um` and `PlanetaryStageSpec.planet_ring_f_ma_um` accept finite nonnegative numbers in micrometres. `None` keeps the previous estimate; `0` is supplied, never missing. Planetary fields address the two meshes independently, including the planet2/ring mesh in stepped stages. Point, spectrum and peak stage evaluations share this path; preset thresholds are unchanged.
Routes/page adapters must pass these stage fields through `GearboxRequest`; they are not `GearSpec` fields. Keep two planetary inputs beside accuracy grade, with units and tooltips. No route or UI code is changed here.
The canonical schema remains v1. Only these additive inputs and the additive source field use omitted defaults: unset inputs and their availability entries are omitted, so old request hashes and entire old result envelopes stay byte-identical under the same canonical JSON encoding. Supplied inputs, including zero, carry `metric_availability` status `available`. Build via constructors/`to_dict()`; explicit null/default entries are not canonical. Unknown fields, missing existing required fields, bad values and inconsistent availability still reject.
`load_factors.f_ma_source` is `supplied` or `estimated`. Supplied results serialize `f_ma_source="supplied"`; in legacy JSON an absent source means `estimated` and the existing estimate caveat remains. The strict decoder restores the default and rejects a source inconsistent with the estimate caveat/missing-input markers. Supplying f_ma removes only its estimate caveat/missing-input entry and the corresponding member flag; load factors remain `estimated`.
The input replaces **only** `f_ma = 0.5*f_pt + 0.08*b` in the existing model. It is the manufacturing/assembly misalignment contribution, not total effective mesh deviation. The independent placeholder `f_sh = 0.023*(F_m/b)*(b/d1)^2*10` remains, with `F_bx = 1.33*f_sh + f_ma`, `y_beta = min(0.15*F_bx,6 um)`, and `F_by = max(F_bx-y_beta,0)`. Do not enter measured total loaded misalignment as f_ma without separating the shaft contribution; this would double-count it. The legacy missing-input label mentions shaft/housing deflection but is not a definition of this newly exposed input.
`r = F_by*c_gamma_beta / (2*max((F_m/b)*K_v,1 N/mm))`; `K_Hbeta=1+r` for r<=1 (full-width contact), otherwise `2*sqrt(r)` (partial contact). The existing load floor and running-in/stiffness approximations are unchanged. No `c_beta_um`/`C_beta_um` relief input is implemented: the model has no verified crowning/end-relief term. Stiffness c_gamma_beta is not crowning C_beta.
Validity remains estimated screening in the existing domain: alpha_n 15-25 degrees, abs(beta)<=30 degrees, epsilon_alpha 1-2.5, admissible metallic gear geometry and rim/root gates. The numerical boundary accepts any finite f_ma>=0; it is not a physically qualified tolerance range. Independent hand checks exercise both contact branches and the running-in cap of this implemented model, not a full ISO or measured validation. Internal-root bending remains unsupported.
Illustrative robot stage: m0.6, z20/40/100, b10.5 mm, three planets, ring fixed, 600 rpm sun, 40 Nm carrier output, 70 C, grade6, default carburised material, ROBOT_GREASE_NLGI1_PAO, tooth thinning0.02 mm. Default f_ma=4.395706 um gives K_Hbeta=3.137318 and mesh min_S_H=0.654965; supplied1 um gives 2.688551/0.689450; supplied10 um gives 3.762670/0.614533. These assumed values show sensitivity, not a recommended tolerance. The brief's rounded 3.03/0.61 is not exactly reproducible without its complete payload. None qualifies; the shaft placeholder continues to dominate.
`floating_member=True` selects the existing estimated planet load-sharing K_gamma default. It does not solve floating-sun self-alignment or shaft/carrier/housing compliance and gives no independent f_ma reduction. No new floating-sun mechanics is implemented.

### Optional shaft/pin mesh misalignment input (f_sh)

`PairStageSpec.f_sh_um`, `PlanetaryStageSpec.sun_planet_f_sh_um` and `PlanetaryStageSpec.planet_ring_f_sh_um` accept finite nonnegative numbers in micrometres (not booleans or numeric strings). `None`/absent retains the exact previous estimate; zero is supplied. Planetary inputs are independent, including stepped planet2/ring meshes. They pass through schema-v1 `GearboxRequest`, point, spectrum and peak evaluations. Low-level `rate_pair_iso6336` and `compute_iso6336_load_factors` also accept `f_sh_um`. Thresholds are unchanged.

The value replaces only `f_sh` **before** the existing `1.33` multiplier: `F_bx = 1.33*f_sh + f_ma`, `y_beta = min(0.15*F_bx,6 um)`, `F_by = max(F_bx-y_beta,0)`. It is a mesh-face misalignment contribution from deflection, not a centre translation, total loaded `F_bx/F_by`, manufacturing error or an angle. Separate these contributions before supplying them. A supplied stage value is held constant at every duty/peak evaluation; for spectrum/peak screening, the caller must supply the conservative maximum f_sh applicable across all duty bins and the declared peak (the core does not rescale it with torque); reusing a rated-load deflection at a higher peak can understate K_Hbeta. `floating_member` does not zero it automatically.

Fresh Python `load_factors` reports actual `f_sh_um` and `f_sh_source` (`supplied`/`estimated`). For exact legacy v1 compatibility, estimated `f_sh_um` and the default source are omitted from serialized results; old JSON did not retain this diagnostic. Decoding such a record gives `f_sh_um=None`, `f_sh_source="estimated"`; rerun the request for its numerical estimate. Supplied results serialize both fields and numeric metric availability. The strict decoder rejects a source inconsistent with the shaft-placeholder flag or a supplied source without a finite nonnegative value. Request defaults and their availability entries are omitted, as for f_ma; explicit null is not canonical.

Supplying f_sh removes only `simplified:placeholder_shaft_bending_f_sh`. It leaves the independent f_ma estimate/caveat, fixed Bk/mass model and running-in approximations intact; `load_factors.state` stays `estimated` even when both misalignment inputs are supplied. The screening domain remains alpha_n 15-25 degrees, abs(beta)<=30 degrees, epsilon_alpha 1-2.5, admissible metallic geometry and existing rim/root gates. A finite input is not a physically qualified misalignment range. Internal-root bending remains unsupported.

At f_sh=0.11 um, `1.33*f_sh=0.1463 um` versus f_ma=4.395706/4.712221 um: manufacturing/assembly now dominates F_bx in both meshes. Sun/planet still fails; no safe design is claimed. Its baseline f_sh is 6.306953 um for this fully specified fixture, not the brief's approximate 7.9 um. The placeholder uses F_m/b **before** K_v; the face-factor denominator includes K_v. The remote original payload is unavailable, so this reuses #930's reproducible example rather than claiming exact reproduction of the quoted 3.03/0.605.

No automatic `PlanetPinSpec` compliance model is added. The brief's ideal simply supported, centrally loaded hollow pin has `I=pi*(12^4-6^4)/64=954.258769 mm^4`; assuming `E=206000 N/mm^2`, `delta=950*10.5^3/(48*206000*954.258769)=0.000116551 mm=0.116551 um`. The ideal maximum slope is `950*10.5^2/(16*206000*954.258769)=0.033300 um/mm` at the supports, and zero at midspan. See [MIT, Roylance, Beam Displacements, equations 6-7](https://web.mit.edu/course/3/3.11/www/modules/bdisp.pdf). This verifies bending-only arithmetic, not face misalignment: span/diameter=0.875 is not a slender beam; shear, bearing load transfer/tilt, plate compliance and press-fit rotational restraint are unresolved. The given diameter/bore/E/span/support/load position alone cannot determine the relative mesh-face alignment. Existing PlanetPinSpec strength calculations remain unchanged; no hollow-section strength support is implied.

## Limitations the UI must show

- Internal-root bending remains unsupported (including cutter-count-only inputs); thin-rim unsupported gates remain. Complete planetary life/qualification cannot be green while a required root/history is unavailable.
- Signed reversal/contact-history fatigue remains unsupported. Simple-planet peak screening uses the worse mesh stress; it does not resolve alternating two-flank history. Endurance means unlimited only within the supported Miner/S-N model, never unlimited physical service life.
- Stress above an S-N static plateau is out of domain. Static tooth-root/hardened-flank safety requires provenanced, temperature-matched allowables; fatigue plateaux/core yield are not substitutes. Static screening domain remains alpha15-25 degrees, abs(beta)<=30 degrees, epsilon_alpha1-2.5 plus geometry/root gates.
- F5 helical YF load-point interpolation remains unverified against ISO6336-3:2019. Mesh-loss correlation, bearing friction/ISO281, K_v/K_Hbeta/K_Halpha, Y_beta, internal geometry, DIN743 factors, carrier/pin/rim, thermal balance, stiffness/mass/inertia, IR and CAD outlines lack complete independent literature/measured qualification.
- Generic material cards and ISO factor estimates, grease/contact-temperature assumptions, preload and thermal UA remain estimates. A passing preset is screening with supplied modeled parts; omitted optional part definitions are not a mechanical certification. Missing support/static inputs must remain visible.
- Forces use nominal equal branch vectors and adversely aligned external load magnitudes; unequal branch vectors/general seats/overhangs/overturning/housing mechanics remain unmodelled. Oil-churning reaction allocation remains estimated. Missing mesh efficiency/nonconvergence gives unavailable efficiency; static torque seeds are diagnostic only.
- Failed/unsupported bearing spectra have no aggregate life; individual finite L10 values in failed records are diagnostic. Blank bounds exclude housing. Sampled/decimated outlines are viewer geometry, not manufacturing CAD or 3-D clearance certification.
- Use short labels/tooltips and visible validation errors; display availability/state with values and never turn missing metrics into green passes. No customer-facing screens changed.
