# Interface languages (i18n)

The owner asked (2026-09-29) for the UI language to be switchable, with
Simplified Chinese first, because most suppliers are in China. The rule is the
same one the marketing site uses: **EN is the source, and zh-CN is a full
mirror.**

## Library choice

We use **i18next + react-i18next + i18next-icu (ICU MessageFormat)**, with
`i18next-resources-to-backend` for lazy namespaces.

- It is the most widely used and actively maintained React i18n stack. It
  handles lazy namespaces, fallback languages, missing-key hooks and plurals out
  of the box.
- It works at runtime from JSON, so there is no compile step and no Babel/SWC
  macro. We considered LinguiJS, a good library that extracts messages at build
  time. It would have required a macro plugin in `vite.config.ts` and edits at
  every call site in a style that conflicts with open PRs #41–#51, which touch
  the same files. i18next leaves the build unchanged.
- ICU MessageFormat (`{count, plural, one {# motor} other {# motors}}`) is the
  standard format that translators and TMS tools read. Chinese has a single
  plural form, and `Intl.PluralRules` handles that automatically.

## Layout

```
web/src/i18n/
  core.ts        createI18n(): the i18next instance, ICU, lazy backend, EN fallback, dev warnings
  index.ts       the app instance (locale detected at startup)
  locale.ts      supported locales, detection, localStorage (every access in try/catch)
  persist.ts     setLocale() (localStorage + PUT /api/me/preferences), useServerLocale()
  format.ts      Intl number/percent/date helpers; unit symbols pass through untouched
  errors.ts      translateApiError(): uses the API error code, falls back to the English detail
  nsT.ts         namespace-bound translator used by large panels (tx('key'))
  __tests__/     key-parity and runtime tests (node --test)
web/src/locales/<lng>/<ns>.json   namespaces: common, errors, help, motors, geometry,
                                  simulation, results, controller, thermal, admin
web/src/locales/GLOSSARY.md       EN ↔ ZH terminology (use it for every new string)
```

- `common` and `errors` load with the shell. Every other namespace is
  **lazy-loaded**: Vite emits one small chunk per `<lng>/<ns>.json`, and a
  panel's main component calls `useTranslation('<ns>')`, which loads the chunk
  the first time the tab opens. English is shown until the chunk arrives,
  never a blank screen.
- **Fallback:** a key that is missing in zh-CN renders in English. In dev
  builds, the console warns once per namespace with the missing keys.
- **Language choice:** the switcher is in the account menu. Signed-out visitors
  get a header icon so they can read the landing page and sign-in dialog. The
  selection order is: the user's server preference → `localStorage['ui.locale']`
  → `navigator.languages` (any `zh-*` maps to zh-CN) → English. `<html lang>`
  follows the chosen language.
- **Server preference:** `GET/PUT /api/me/preferences` `{locale}` is stored per
  e-mail in `.user_prefs.json` beside the panel settings. localStorage is the
  fallback when signed out or when the call fails.

## Rules for strings

1. **Never translate unit symbols or physical-quantity symbols.** Examples:
   `N·m`, `kW`, `rpm`, `°C`, `A rms`, `T_j`, `Br`, `HcJ`, `L_d`, `η`, `γ`,
   `cos φ`. Engineers read them the same way in every language. Use
   `formatQuantity(value, unit, locale)`: digits follow the locale, the unit
   symbol is untouched, and it uses SI spacing.
2. Numbers and dates go through `Intl` (`i18n/format.ts`). Do not hand-roll
   separators.
3. Put placeholders in the message (`{min}`, `{email}`). Do not concatenate
   strings. The parity test checks that every translation uses exactly the
   placeholders of its English source.
4. HelpTips: `<HelpTip i18nKey="controller.someKey" />`. The default namespace
   is `help`. If `title` is also passed, it is the English fallback.
5. Tab labels in `App.tsx` stay plain string literals because
   `tests/test_support_chat_limits.py` reads them. They are translated at render
   time through `common:tabs.<id>`. In English, the module-manifest title still
   takes precedence, as before.
6. New Chinese terms go into `locales/GLOSSARY.md` first.

## Checks

```
cd web
npm run test:i18n       # key parity (missing zh keys reported, not fatal; extra keys,
                        # bad ICU, placeholder mismatches fail) + runtime tests
npm run i18n:coverage   # heuristic count of literal UI strings left, per file
```

## Backend error codes

`src/motor_ai_sim/api_errors.py` adds `code` and `params` next to the
**unchanged** English `detail` on every `HTTPException` answer. Existing
clients, and the MCP/agent surface, keep reading `detail`.

- New code raises `ApiError(status, "area.reason", "English message", {params})`.
- About 500 existing `HTTPException(..., detail="...")` sites were left
  untouched to avoid conflicts with open PRs. `classify()` maps their English
  text to codes, and anything unmatched gets `http.<status>`. The web shows the
  English `detail` for codes it does not know.
- FastAPI request-validation 422s already carry stable pydantic `type` codes
  (`missing`, `greater_than`, …) with `ctx` parameters. They are unchanged, and
  the web can key on `type` later.
- The web-side codes are in `locales/<lng>/errors.json`, and
  `i18n/errors.ts:translateApiError` renders them.

## Report / datasheet PDF localisation: plan only

This PR does not implement it. The plan:

1. **Font:** the PDF renderer's built-in fonts have no CJK glyphs. Bundle
   **Noto Sans CJK SC** (or **Source Han Sans SC**, the same design). Both are
   under the **SIL Open Font License 1.1**, which allows embedding and
   redistribution, including in commercial PDFs, if the font is not sold on its
   own. That is compatible with the repo's Apache-2.0 licence, and the licence text ships
   next to the font file. Subset the font per document (tens of kB instead of
   about 16 MB) and register it as the fallback for CJK code points only, so
   Latin text and the typography from the 2026-09-11 report conventions stay
   unchanged.
2. **Strings:** move report captions, table headers and warning lines into a
   Python catalog. Use `gettext` `.po` files, or JSON that mirrors the web
   keys, so one glossary serves both. The report route takes `?lang=` and
   defaults to the requesting user's preference.
3. **Numbers:** use the same rules as the web. The locale sets separators, and
   units and symbols stay as they are. The `.xlsx` datasheet only needs
   translated header cells, because Sheets/Excel handle CJK natively.
4. **Verification:** render one L155 report in zh-CN and check glyph coverage
   (no tofu boxes), line wrapping in table cells, and that every number matches
   the EN report exactly.

## Agents and MCP stay English

The MCP server, agent tool descriptions, the agent API, logs, yaml keys and the
support-assistant system prompt stay **English only**. They are machine-facing
contracts and a shared engineering vocabulary, and translating them would fork
the tool semantics. Agents that need Chinese output translate at their own
edge. API error bodies keep the English `detail`, and `code` is additive.
